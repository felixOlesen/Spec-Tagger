# SpecTagger

SpecTagger is a symbolic test execution tool that uses tags in your documentation and test suite code to execute tests based on their relevance to the part of the documentation that you have tagged.

# How it Works

## Testing

1. You can tag items in your specification/documentation:

```
feat~booking_flight_tickets~1
The flight ticket feature works by logging in, 
checking flights and ...
```

1. You can then tag a related test case with the exact same tag to symbolically link them:

```
# feat~booking_flight_tickets~1
def test_booking_flight_ticket():
...
```

And then by running ```spectagger``` it will crawl through the specification and test directories to find tags and execute tests by-tag, giving you observability into how your documented functionality is being realised in the source code.

## Spec Review

The spec review process lets the tool review the generated json report, and provide LLM insight by sending an overview of the changes to an LLM endpoint that you provide. Giving you an understanding of any ways that your spec might be drifting from your tests and source code or vice versa.

# Getting Started

## Installation

You can install the tool by either:

Cloning it locally and running ```pip install -e .``` inside the repository root.

OR

```
pip install "git+https://github.com/felixOlesen/Spec-Tagger@v0.0.9" 
```

(Change ```v0.0.9``` to whatever the latest release of the project is.)

## Usage

You can invoke spectagger by running ```spectagger``` in your terminal in the project that you have tagged.

To get everything running, you need to define a series or variables and pass them into the command as args or put them in a .env file for the tool to identify.

To get a list of all of the available arguments run:
```spectagger --help```

You can do the same for the ```spec-review``` and ```merge-analysis``` sub commands as well.

*.env setup*
Here is a list of all of the .env variables you can define:

```

SPECREVIEW_REPORT_INPUT= The file path to your report.json generated by running a spectagger test run

SPECREVIEW_MODEL_PROVIDER= The name of your model provider according to and supported by LiteLLM

SPECREVIEW_MODEL_NAME= The name of the model according to LiteLLM and supported by the provider

SPECREVIEW_RATE_LIMIT= The rate limit of the model you're using, Default is "10" requests per minute

SPECREVIEW_SRC_DIR= The Directory containing your source code

SPECREVIEW_GIT_BASE= What the git base is for how far back you want the spec review to compare changes e.g. "origin/main"

SPECREVIEW_GIT_HEAD= What the git HEAD is for what you want to compare your base with in diffs e.g. "HEAD"

SPECTAGGER_TARGET_SPEC= The directory containing your tagged documentation/feature files

SPECTAGGER_TEST_DIR= The directory containing all of your tagged tests

SPECTAGGER_TEST_COMMAND= The command you use to invoke a test i.e. "pytest {tests}" (include the '{tests}' for the tool ot inject the test cases there.) Here's the command with coverage as well: "coverage run --append -m pytest {tests}"

SPECTAGGER_TEST_FORMAT= The format that your testing framework uses for running an individul test e.g. "{file}::{name}" == "test_file.py::test_function_name"

SPECTAGGER_REPORT_OUTPUT= The directory that you want your report saved to

SPECTAGGER_REPORT_TYPE= Either json, html, or stdout (json is required for the spectagger spec-review to work)

SPECTAGGER_COVERAGE_REPORT_PATH= The directory you want to save your coverage reports to

SPECTAGGER_COVERAGE_LIBRARY= The coverage library that you're using e.g. python.coverage, ruby.simplecov, etc.

# Also be sure to include your API key that LiteLLM can pick up
```

Once you have understood and defined the arguments mentioned above, you can then run the tool like this:

```
# To generate a report
spectagger --report
```

```
# To do a dry_run, checking that the commands constructed by the tool are what you expected 
spectagger --dry_run
```

```
# To do a tag check, making sure that all of your tags are correctly discovered and constructed 
spectagger --tag_check
```

```
# To invoke a Spec Review 
spectagger spec-review
```

## Compatibility

Currently SpecTagger is only compatible with:

Python

- Pytest: python.pytest
- Coverage: python.coverage

Ruby

- Rspec: ruby.rspec
- Minitest: ruby.minitest
- SimpleCov: ruby.simplecov

If you would like to test out the tool, please use it on projects that support these test frameworks and coverage libraries.
